# The page: tabs and controls

What the page shows and how its controls behave: the tabs, a set page's Auto-fill and its settings, the Gear browser's layout, the How the math works sub-tabs, the level and cap fields, and the Sheets tab. Each control is described by its current rule. How the page is built is in [architecture.md](architecture.md); what the search does with the settings is in [optimizer.md](optimizer.md).

Related pages: [architecture.md](architecture.md) (the store, views and when each area recomputes), [optimizer.md, section 7](optimizer.md#7-the-pages-pool-and-its-filters) (the pool the page hands to the search), [tier-ranking.md](tier-ranking.md), [math.md](../mechanics/math.md), [glossary.md](../glossary.md), [roadmap.md](../roadmap.md).

## 1. The tabs

Pick a job from the icons at the top, then set the synced level, and turn on item level sync with a cap if you want one (how to start is in the [root README](../../README.md#use-it); the level and cap fields are in section 5). The page has two working tabs and one reference tab:

The three tabs are links in a navigation landmark named Sections (`<a href="#/sheets">`, `#/gear`, `#/math/<view>`), the open one marked `aria-current="page"`; the math sub-tabs, the breadcrumb and the name links of the sheet and set lists are links the same way. A plain click (the primary button, no Ctrl, Cmd, Shift or Alt: `plainClick` in `ui/router/plain-click.js`) moves inside the page; any other click is the browser's, so Open in new tab, Ctrl or Cmd click and middle click open the address in a new tab. The screens are sections named by the tab's link or the Gear browser's heading, not tab panels. A tab link selects its tab at once and opens it after one painted frame (`openTab` in `ui/store/app-actions.ts`). If the tab takes longer than 200 ms to open (the first Gear browser open on a slow machine), a layer over the page below the tab bar fades in with "Loading the Gear browser…" ("Loading Sheets…", "Loading math analysis…"); a faster switch shows nothing extra. The layer fades in by CSS opacity only, which the browser keeps animating while the page's script is busy.

1. **Sheets** (opens first): saved sheets, each for one job, level and item level sync, holding gear sets. It has no Job and sync panel (each sheet holds its own) and needs no job chosen. Sections 2 and 6. A set page's **Auto-fill** picks one item per unpinned slot (two rings) from every piece the job can wear, to maximize one stat. Its settings are:
   - two optional tiebreakers and an optional Target GCD;
   - a Materia switch (on by default) that gives each piece its best melds;
   - under **Gear to search**, the **Gear categories** boxes, which leave out gear by how it is obtained (quests, crafting, Savage, PvP, ...; nine of them are off by default).
2. **Gear browser**: one table of real gear for the selected job, with filters and its synced stats, for looking gear up. A name search sits on its title line ("/" jumps to it), with a Slot menu that shows how many pieces each slot has; a Reset button appears after the match count while a filter is set, and a click on a column heading sorts by it (again to flip).

   The table shows 50 matches a page, with page numbers above it. A piece that sync lowers shows its synced numbers in bold, with its own numbers in small type under them. It has its own Gear categories boxes. HQ-capable crafted gear carries the HQ mark (the HQ mark, section 3), and rings that can be worn on both hands ×2. Section 3.
3. **How the math works** (reference), with three sub-tabs. Section 4.

**Addresses.** Every screen has an address in the page's hash, so Back, Forward, reload and bookmarks work (`src/ui/router/`):

| Address | Screen |
| --- | --- |
| `#/sheets` | the sheet manager |
| `#/sheets/<sheetId>` | a sheet's page |
| `#/sheets/<sheetId>/sets/<setId>` | a gear set's page |
| `#/gear` | the Gear browser |
| `#/math/piece`, `#/math/gcd`, `#/math/tiers` | How the math works: Stat Allocation, GCD Scaling, Substat tiers (`#/math` opens the first) |

A bare address, `#/` and an address that names nothing open the sheet manager. The open tab and math view are not saved: the address names them. The links of the sheet lists and the breadcrumb are these addresses, so Open in new tab and Copy link give the screen. The ids are the ones in the saved sheets, so a sheet or set address works only in the browser that saved it; in another it shows a "not found" screen with a button up one level, and the address stays as it is. A tab link, a sheet or set opened and a math view each add a history entry; deleting the open set or sheet, leaving a "not found" address and correcting an address (`#/math` to `#/math/piece`) replace the current one. The Sheets tab link returns to the screen that tab was left on in the session. Back, Forward and a typed address ask the set page's question first when a draft, a running Auto-fill or a waiting result would be lost, as the tab links do: the browser has already moved, so the router moves it back to the entry the page shows (every entry it writes carries its place in history, so it knows how far) and moves again if the player leaves. A typed address that is refused stays ahead in history; a further Back or Forward made while the router is moving the browser back is not asked about. After Back or Forward the focus goes to the screen's heading and the page scrolls to where that history entry was left (the page turns the browser's own scroll restore off, `history.scrollRestoration = 'manual'`, so no other position shows first; a screen left scrolled is scrolled to in the same task that swaps the screen in, with the page held tall enough, so no frame shows it at the top, and the browser's scroll anchoring is off for the page; a tab that is still opening is scrolled once it shows; the positions are kept per entry for the session and over a reload in `sessionStorage` (`gsa-scroll-by-entry`), and a reload scrolls back without moving the focus; the router reads the position as it pushes a new screen, so a late scroll event does not lose it (the deeper of what the scroll events noted and what is read then, as the browser clamps the position while the new screen is swapped in), and reads it as the browser moves (Back, Forward, a typed address) before the screen is swapped, so a wheel scroll the page has not yet heard of, whose scroll event comes a frame later, is not lost either, and a scroll event that finds the page where it was last seen is the screen left's late one, not a position of the new screen; a tab swapped in shorter than its saved position gives up the held height in the frame that places it, so no frame shows blank space). A screen the page opens itself (a tab or sub-tab link, a sheet, gear set or breadcrumb link: a new history entry) starts at the top whatever depth the screen before it was scrolled to: the router puts the page at 0 in the task that swaps the screen in (a tab still opening, once it shows), once, so no frame draws it at the old depth and the player's first scroll on it is not pulled back; the screen left keeps its own position for Back. The page title names the screen (`titleOf` in `ui/router/routes.js`). The Sheets screens take no settings in their address.

**Settings in the address.** The Gear browser and the math views take their own settings in a query after the route (`#/gear?sort=det&min=700`; `ui/router/query.js` reads and writes it, `routes.js` parses and formats the text):

| View | Names |
| --- | --- |
| `#/gear` and `#/math/piece`, first | `job`, `level`, `il` (item level cap: item level sync is on when `il` is present, an empty `il=` is sync on with no cap yet; off when it is not), for the panel of that tab |
| `#/gear` | `q` (name search), `slot`, `min` and `max` (item level), `equip` (equip level), `noexp` (expansions off, a list), `skip` (Gear categories left out, a list), `market` (`0` when off), `sort`, `dir` |
| `#/math/piece` | `slot`, `item` (item level), `subs` (one or two substats, a list), `meld` (materia slots) |
| `#/math/gcd` | `gcdlevel`, `haste` (a job with always-on haste), `speed` |
| `#/math/tiers` | `job` (its own job, apart from the panel; it has no level or item level sync), `tierlevel` |

- A link with a query is the whole view: a name it leaves out is the default, never the reader's saved value. A value that is not valid falls back to the default through the checks a saved setting passes (`restoreBrowseFields` and `restorePieceFields` in `state.js`); a name the view does not have is dropped. A link with no query keeps the reader's saved settings.
- Opening a link applies its settings at once and the page saves them like any edit. The Job and sync panel of the Gear browser and of Stat Allocation is in the address too (`job`, `level`, `il`), set through the store's `setPanel` and checked by `restorePanel`; Substat tiers takes its own job (`setTiersJob`), and GCD Scaling has no job, so a job in its address is dropped: a job it leaves out is the default job, a level the default level, and item level sync is off without `il` (the cap the reader held stays: it is no setting, and a reload keeps the page's own settings). The view's other settings are read for the job and level the link names, and a different job resets what the tab held for the old one (`resetForJob`). `il` is written only while sync is on: with sync off the stored cap is not a setting. No other panel is touched: each tab and sub-tab has its own job.
- The address follows the settings: a change writes the settings that differ from the defaults, in the order above, and replaces the history entry (a change of settings adds none). A change of the search text alone is written once typing pauses for 0.4 s, and the writes are at least 0.1 s apart (browsers limit how often history may change); what is waiting goes into the entry when a tab link leaves it. A tab link to the Gear browser or a math view writes the query of the settings it holds; a bare address stays bare until a setting changes, and a view at its defaults has a bare address (which a reader opens with their own saved settings). A list is written with commas (`noexp=ARR,HW`); an empty `skip=` is no category left out. A typed address or a link opened in the page applies its query, and the address is rewritten as the settings the page now holds. Back, Forward and a reload move between screens, not settings: the page keeps the settings it has and the entry is rewritten to them (the page saves a change that is still waiting when it is hidden, so a reload does not lose it). A value that cannot be written in an address (half of an emoji at the end of a search text cut at 100 characters) is cut or replaced, never an error. Sheets, gear sets and Auto-fill settings never go in an address; sharing them is roadmap A3, which needs its own address family (`#/import` is reserved for A12, `#/share` for A3). The names are public once a link is shared, so they are frozen before the first public release (A17).

## 2. Auto-fill: the search on a set page

A set page's **Auto-fill** fills the set's unpinned rows from every piece the job can wear, with the set's own **Auto-fill settings** (the gear button on the set bar; section 6). The pool it searches and the Gear to search filters are in [optimizer.md, section 7](optimizer.md#7-the-pages-pool-and-its-filters).

In the Auto-fill settings the **goal** is the three ranked stats (Maximize and the two tiebreaks), and the **target** is the first of them, the stat to maximize. A stat holds one rank, so picking one another rank holds swaps them, and a line under the switches says which rank changed ("Tiebreak 1 changed to Mind (a stat holds one rank)."). An Auto-fill's answer is one **gear set**: a piece for every unpinned slot, with melds, and a meal while the meal is not pinned and Food is on.

### Target GCD

The control for the Target GCD layer of [optimizer.md, section 2](optimizer.md#target-gcd-from-a-gcd-to-a-speed-range).

- **Place.** Beside the goal in the Auto-fill settings: the box (empty means any GCD) and "exactly" / "or faster" ("exactly" by default, as in xivgear).
- **Label.** One line over the box and the buttons. At the left: "Target GCD", a middle dot and the range of GCDs the gear reaches, in muted mono ("Target GCD · 2.50–2.10"); this part never shrinks. The range follows the settings as they change: it is one search for the most speed (20 to 100 ms), run in the solver's worker with the piece count. A screen reader reads the whole sentence as the box's name ("Target GCD (2.50 to 2.10)"): it sits in a visually hidden span (`.sr-only`) and the visible parts are `aria-hidden`. The parts come from `gcdLabel` in `src/ui/solve.js` (`name`, `range`, `haste`, `off`, `full`); the template only shows them. The line's height, and so the field's and the popover's, is the same in every state.
- **Box.** It takes 0.50 to 2.50; a higher value moves to 2.50 when the box is left (2.50 is the slowest base GCD).
- **Haste jobs.** For Monk, Ninja, Samurai and Viper the label also names the haste at the right end of the line, in muted sans ("Fuka 13%", "Increase Attack Speed 15%"), and the box takes the hasted GCD. When the two collide, the haste is cut with an ellipsis (its `title` has the full text); the name and range are never cut. A job without an always-on haste has no right part.
- **Messages.** When no gear set fits, the Auto-fill says why in a line under the header ("Ninja's GCD is 2.12 at most (Increase Attack Speed 15%)", "The GCD can't go below 1.50", "No set at exactly 2.10").
- **Off.** The box and buttons are disabled while the goal is the speed stat; the line then reads "Target GCD" at the left and "Off: goal is speed" at the right, and the box's name is "Target GCD (off: the target is speed)".

### Running an Auto-fill

The search runs only when the player presses Auto-fill, in the set's own lane of the solver's worker ([architecture.md, section 9](architecture.md#9-the-optimizers-worker)), so the page stays free.

- **While it runs.** Auto-fill becomes "Solving…" with a **Cancel** button, and every edit on the tab is off. Cancel stops the search in the worker and leaves the set as it was.
- **Its answer** waits as a suggestion with Take boxes (section 6). An Auto-fill that finds nothing, or a pin no set can keep, says why in a line under the header; an unusable piece or meal is unpinned and the line says so (the Nothing found paragraph below has the lines).
- **If it fails.** A search that fails (not a cancel) says so in the same line, with its reason; the set stays as it was.

### Spare points to tiebreaks (rank by tier)

Roadmap A7. A switch in the Auto-fill settings, beside Materia and Food.

- **Default.** **On**. It is dimmed and disabled until Tiebreak 1 is set: with no tiebreak there is nothing to send spare points to.
- **Label and note.** The ? note reads "Substats only improve at tiers, so points short of the next tier do nothing in game. This sends those spare points to your tiebreaks instead." "Tier" is the community's word (AkhMorning, The Balance, xivgear); "wasted" is avoided, since melding guides use it for materia past an item's cap.
- **What it does.** On, the search is tier ranking ([tier-ranking.md](tier-ranking.md)): meal and gear are chosen together, with or without a Target GCD, since every tier counts food.

### Character panel totals

A set's Total row shows each substat as the in-game character panel does: the level's base plus gear plus food; [math.md, section 6](../mechanics/math.md#totals-as-on-the-character-panel). Main stat and Vitality also start from the job's base (the level's base main stat times the job's modifier). They leave out the clan's bonus and the party bonus unless the sheet sets them (`sheet.clan`, `sheet.partyRoles`); then `evaluateSet` counts them in `panel` and `panelGear` (with and without the meal), and the Total row, the header's main-stat and Critical Hit figures and the sheet list's Stat points tab all read those two maps. `bonusNote(sheet)` in `set-totals.js` gives the note under the Gear sets table that says what was counted ('' when none). The optimizer and Auto-fill never count either bonus.

The Total row's item level cell shows the set's average item level, a whole number (`Math.round`) with a leading `~` (no space) that marks it as an average, set in italic (`pieces.css`), as the panel's figure is: the worn pieces' own item levels (never the synced ones) over 12 slots, empty slots counting 0, the meal not counted. It is blank when nothing is worn. The rule is `averageItemLevel` in `core/set.js` ([math.md, section 6](../mechanics/math.md#average-item-level)); `setTotalsView` gives the text as `total.ilvl` ("~77", with the tilde in the text so one place owns it) and the cell's `aria-label` as `total.ilvlLabel` ("Average item level 77"). The cell has no hover title.

### Which piece an Auto-fill suggests

Roadmap A9. Under sync many pieces reach the same caps: for Sage at level 50, cap 123, with crafted and tomestone gear, every slot has 11 to 20 others. An Auto-fill suggests, for each row, the piece with the same result that is easiest to get: the lowest equip level, then the lowest item level, the search's own pick on a tie (`core/same-result.js`).

- **The same result:** the same main stat, and every substat at the same tier, counted with the set's meal. The tiers are tier ranking's (`rankTierOf`, [tier-ranking.md](tier-ranking.md)). The goal stat's raw points stay as well. Two tiers may drop a step:
  - speed holds its GCD (with haste) but its DoT/HoT tick scaling may drop a step (**owner's decision**, as for tier ranking);
  - Tenacity holds its mitigation step (200) but its damage bonus may drop a step (**owner's decision**).
- **Rows share their spare points.** Two swaps can each keep a tier alone and lose it together, so every check is made against the pieces the other rows show: rows are filled in panel order. A Unique piece is never in two rows (rings), and a piece must leave the same slots empty as the search's pick (a cloak never replaces a plain body).
- **The meal** an Auto-fill suggests is the highest item level meal with the best meal's result (`sameMeals`).

### The Food row's menu

The Food row's meal on a set page is a menu (`components/meal-menu.js`, `views/meal-menu.js`), with "No food" first while the set has a meal.

- **The menu** lists every meal the job can use (`allMeals`; 182 for Astrologian), by expansion, newest first, one line each. The set's meal is lit. A line holds:
  - its item level first ("i580", as players write it);
  - its name;
  - what it adds on the set's gear, in the meal's own order, its main stat first and Vitality last ("SpS +44 DHT +41 VIT +54").
- **Filters.** A search box (meal names) and stat pills (CRT, DET, DHT, SpS, PIE; a meal must have each pill picked) narrow the list.
  - *Start:* the pills start empty, then stay as the player leaves them unless they would leave the list empty for the menu opened; then they start over.
  - *Grey pills:* a pill greys out only for a real reason: a third one (a meal has at most two stats), or one that would leave the list empty under the other filters.
  - *Empty list:* so only a search can empty the list, which then says so: "No meal matches "xyz". Clear search" (`mealsPassing`, `mealPillOff`, `mealEmptyReason`; a unit test walks every state the menu can reach).
- **Picked stats as chips.** A stat on a picked pill is drawn as a soft accent chip in every meal's line. The line is view data (`adds`, `mealLine`), not a string.
- **Sort.** While a pill is on, a row under the search box reads "Sort: ILVL / CRT" ("ILVL / CRT / DET" with two pills, in the pills' order).
  - ILVL is the expansion grouping, highest item level first.
  - A stat sorts the list by the points the meal adds on the set's gear, highest first, then by the other picked stat, ties newest first, as one list.
  - Turning off the sorted stat's pill goes back to ILVL (`sortMeals`, `mealList`).
- **Best for goal.** It applies to a set Auto-fill made and nobody changed since (the saved `bestMeals`, [sheets.md](sheets.md#saved-data); a waiting result, or a draft that changes a piece or a stone, has none; a draft of the meal alone keeps it).
  - *Star:* the Food row shows a gold star beside the meal (its accessible name is "best for goal"), and the menu's tool row has a "Best for goal" switch with the same star before its label.
  - *Switch:* it is on the first time the menu opens, then stays as the player left it (while the page stays open). On, the list is the tagged meals and the pills are cleared (turning the switch on clears them).
  - *Your pick:* with the switch on or off, the meal the set holds leads the list alone under "Your pick" (when it passes the search and the pills), even if it is not tagged.
  - *Off:* every meal is listed and the tagged ones wear the star after their name (`mealBestKeys`, `mealBestNote`; `mealsPassing`'s `bestOnly`).
  - *The star's drawing:* it is the `best` class from `mealList`'s `rowClass`, a CSS mask on the name's `::after` with the words as its alt text, so a row has no extra element.
  - *Hand pick:* a meal picked by hand wears no pill, but the switch and the tagged meals stay.
- **A meal picked** is a change by hand: it makes a draft and pins the meal (section 6).

## 3. The Gear browser tab

The database matches of the tab's own filters, with synced stats; when it recomputes is in [architecture.md, section 3](architecture.md#heavy-work-debounced-only-when-visible-or-on-request).

**Layout.** The title line holds the heading, one round search bar, the match count and Reset. The bar has a single border (on `.searchbar`, which turns to the accent colour while either part has focus) and two parts: the **Slot** button at its left, a thin divider, then the name search (every word must be in the name, the words found are marked). Under the title line is one row of filters (item level as one "min – max" field, as under Gear to search). A Reset button (funnel and ×) sits after the match count while any filter is off its default (`browseFiltered`; its place is kept while hidden, so the search bar does not change width when it appears). Sorting is from the column headings (`browse.sort` and `browse.dir`, saved).

**The Slot menu** (`#b-slot`, its menu `#b-slots`): the closed button names the chosen slot ("Any slot", "Necklace"; `view.slotLabel`) and opens a list in the Expansion menu's own row style: "Any slot" first, then the job's slots in the order weapon, off-hand, armor, accessories (`view.slots`), each with the number of matches under the other filters at the right in mono type (`countText`, with thousands separators). A slot with no match is greyed out and cannot be picked, unless it is the chosen one; the chosen slot is bold. It is the element `<gsa-slot-menu>` (a Zag menu with radio items; the chosen row has `aria-checked`). **Keys:** ArrowDown, Enter or Space on the button opens the list with the chosen slot lit (the first when none is chosen); ArrowUp opens it with the last slot lit; the arrows move the light and skip a slot with no match, Home and End go to the first and last, Enter or Space picks the lit slot. A click or a tap opens it with no row lit. A choice (`browse.type`) closes the menu with the focus back on the button; so do Escape and a click outside. Tab closes it and the focus moves on to the next control; Shift+Tab goes to the control before the button. A script that moves the focus to another control closes it and leaves the focus there. The list is one tab stop: the focus stays on the list, and the lit row is its `aria-activedescendant`. **The lit row:** a row lit by the arrow keys has a 2 px ring in the accent colour (the focus ring of the page's other controls, inset), over the tint; a row lit by the pointer has the tint only; the chosen row is bold with the tint, and in forced colours it has a thin outline and the lit row a thick one in the system highlight colour. A press or a tap in the element hides the button's focus ring when the focus comes back to it (the ring is for the keyboard; any key press on the page ends that, so a focus that arrives by key always shows its ring, wherever the pointer last was), and a drag over the rows selects no text. A tap on the button opens the menu in every engine (the trigger's `pointerdown` is cancelled for the mouse only). **Width:** the button is as wide as the menu needs, and the open menu is exactly as wide as the button: a hidden copy of the rows (`.slot-sizer`, with the widest count the list can show, 99,999) shares the button's grid cell, so the width comes from the longest slot name and that count, never changes with the choice or the numbers, and nothing clips (smoke step `checkSlotMenu`, which also sets every number to 88,888 and measures at 960, 1280 and 1920 px). Zag's positioner hangs the menu under the button (4 px below it) and keeps it inside the window on the sides. **Height:** the list is no taller than the room on the side of the button it opens on (Zag's `--available-height`, read by `.slot-menu` with a least height of 6.5 rem) and scrolls inside when it is taller: it opens below the button, and above it only when the window has less room below than above. Zag keeps the lit row in view in the list, the wheel scrolls the list and does not carry on to the page, and the list is never taller than the window or above its top, so every row is reachable by the keys and the wheel at 1366 x 650, 1280 x 500 and 960 x 420 as at 1920 x 1080 (smoke step `checkSlotMenuShortWindow`; the stories do it at six window sizes); the positioner is as wide as the button from the first frame (CSS), so the menu never shows at another width.

**The Gear categories control** (the browser's and the Auto-fill settings'): one dropdown menu that carries what each box covers; the closed field shows the count only ("11 of 20", "All", "None", "All but N"; `gearFromSummary`). It is the element `<gsa-gear-categories>` (a Zag popover; the tabs are `<gsa-gear-sections>`, a Zag tabs machine). An 18 px Remix `store-2-line` stall sits between the count and the chevron in both states (`marketWords`): gold with the accessible name and the button's `title` "Market board gear included" when market board gear is included (the default), and the delete button's red (`--danger`) with a slash (a 2 px stroke from bottom left to top right, with a 5-unit gap in the page background colour around it) and "Market board gear not included" when it is left out. The count is never clipped at 960 px. The menu is as wide as its box titles and their numbers need and at least 436 px (the least that fits the longest hint on two lines; `width: max-content` with that `min-width` and a `max-width` of the window less 16 px, and `contain: inline-size` on the hints so they do not count toward the width): 492 px with the page's font, the same at every window width from 960 px up (no breakpoint) and whatever the numbers, and it has one height for every tab (all tabs' panels share one grid cell, the ones not selected `visibility: hidden`, so the tallest tab, Everyday, sets it and switching tabs never resizes it). Its head holds the "Include market board gear" switch at the left (the label only, no text under it; it is not a box and no tab) and All, None and Default at the right (they apply to the 20 boxes, not the switch). Under it is a tab row (`role="tablist"`): Everyday, Side content and Hard content, each with its ticked count ("Everyday 7/8"; `tabCountText`), and the selected tab's boxes in two columns, each a checkbox, the name in bold with the number of pieces at the right end of its title line (below), and its text (`hint` in `item-format.json`) under it in muted type, two lines at most. Everyday and Side content read down each column (4 + 4 and 4 + 3); Hard content reads across, two to a row: Extreme (Current) | Extreme (Legacy), Savage (Current) | Savage (Legacy), Ultimate (`order` in `FROM_SECTIONS`: the data's box order is fixed by the route bits). Events & promotions is the last box of Side content, after PvP. `GEAR_FROM_SECTIONS` builds the tabs. Everyday is selected first and the last tab is kept while the control lives (the Auto-fill settings' control is new each time the settings open). The tabs follow the WAI-ARIA tabs pattern: Left and Right move and select (wrapping), Home and End jump (Zag's tabs), only the selected tab is in the Tab order. The Tab order is the switch, the tabs, the selected tab's boxes, then All / None / Default (they come last in the markup and the CSS puts them in the head). Escape closes the menu with the focus back on the field's button (in the Auto-fill settings the next one closes the settings); a click outside closes it. **The piece count of a box** (`.from-count`): how many pieces of the pool its category holds under the current filters, in mono type (`var(--mono)`, 0.72rem, tabular numbers), right-aligned in a fixed 6-character column so the menu does not change width as the numbers change, with thousands separators (`gearFromCountText`: "1,380"), in the muted colour; a 0 is gold and bold (`.zero`). Nothing is dimmed: a box with no piece is ticked and unticked like any other. A piece obtainable in two ways counts in both boxes, so the numbers can add up to more than the pool; they do not depend on the boxes ticked or on the market board switch (`activityCounts`, core/items.js). The Gear browser's numbers are those of its rows under the job, sync, search and filters and the slot pill chosen (`view.fromCounts`, from `gearView`); the Auto-fill settings' are those of the Auto-fill pool (Gear to search: wearable pieces, relics whose substats the player allocates left out), counted by the solver request `gearToSearch` (`gearFromCounts`, `fromCounts` in `gearToSearchView`) and so arrive a moment after the settings open or change; until a count has landed, and after a change of the job or of a filter the numbers depend on (expansions, item level range, equip level) until the new one lands, no number is shown (not a 0); ticking a box or the switch keeps them. The number is `aria-hidden`; each box's `aria-describedby` holds the hint and a hidden sentence (`fromCountWords`: "1,380 pieces in this category under the current filters.", "1 piece in ...", "No pieces in this category for this job and filters.") and the row's `title` is the same sentence. The tab badges and the closed field's summary count ticked boxes and are not affected. The menu's right edge is on the field's (it is wider than the field), so it stays over the page's card (the content column, 1,280 px at most) at every window width. In the Gear browser the menu hangs under its field and scrolls with the page; in the Auto-fill settings it is fixed to the window (section 2, floating menus). Both open over the field (ending 4 px over its label) when there is more room above, and are cut to the room on their side (Zag's `--available-height`) with a scroll of their own.

**Rows and cells.**

- A row that sync lowers shows what the player gets on top, bold: the synced stats, the lowered ones with the cap bar; a muted line under each holds the piece's own value, and a grey bar marks the row's left edge (`browseCell`).
- The key above each table reads "max while synced" beside a barred sample.
- The item level column shows the piece's own item level, in the browser and on a set page alike (the synced one there would confuse).
- The table keeps its 50 rows between actions: a sort, a page, a slot, a filter or a job change rebinds them, so the table never empties and the page does not rebuild it. The HQ mark and the x2 mark follow the item at once (`:hidden`); the rule is in [architecture.md, section 3](architecture.md#3-the-ui-pattern).
- The browser's table has fixed column widths (`table-layout: fixed`; a width per column kind: Slot, Lv, Ilvl, each stat), so a sort or another page never moves a column. Slot is the first column, wide enough for its longest line (100 px; a piece of three or more slots, such as "Body + Hands + Legs + Feet", goes on two lines); the number columns hold a 4-digit value; Item takes the rest and cuts a long name with an ellipsis (the full text is the cell's title). Every sortable heading keeps room for its sort arrow, hidden until the column is the sorted one.
- The column the table is sorted by has its number cells tinted in the soft accent (the Gear browser's, by a rule from `columnTintCss`). Only the Gear browser tints the pointer's row and column or the sorted column; the gear sets list tints its row under the pointer only.
- The column under the pointer is tinted (cells) and its heading takes the text colour, for every column but Item and Slot. The component holds the column's key in `hotCol`; `columnTintCss` (`views/gear.js`) turns it and the sorted column's key into the rules of one `<style>` element in the page, so no cell carries a class for it (a binding on every cell made a sort 20 ms slower).

**Pages.**

- The table shows 50 matches a page (`PAGE_SIZE`; the time to sort or turn a page is mostly the time to draw the rows, about 1.3 ms each). The title line gives the number of matches ("2,156 matches").
- The page numbers sit at the left of the key's line above the table, and the key at its right. The line always shows, even with one page and no key, so the table does not move as they come and go.
- With more than 7 pages, the line keeps 7 number places between the ‹ and › arrows. They hold the first page, the last, the current one with one page each side, and "…" for the pages skipped (‹ 1 … 8 9 10 … 22 ›). Near an end the numbers run on from that end (‹ 1 2 3 4 5 … 22 ›). With one page there are no numbers (`pageList`).
- Each number and arrow is a button; the current page has `aria-current="page"`, and the arrows are disabled at the ends. A page change scrolls the table's box to its first row.
- Any change to the list (a filter, the search, a slot, the sort, the job, the level or sync) goes back to page 1, also when the old setting comes back. The page is not saved: a reload starts at page 1.

**The HQ mark** (`.hqg`, `ui/hq-font.js`): after the name of HQ-capable gear and of the meal in the Food row. It is plain "(HQ)" in the muted colour until the Lodestone symbol font (hotlinked from the ewwwin/ffxiv-symbol-fonts mirror, pinned to one commit) has loaded, then `html.hqfont` swaps in the glyph; offline or blocked, the text stays.

## 4. The How the math works tab

A reference tab with three sub-tabs, each on its own settings where noted:

- **Stat Allocation**: what sync does to one piece, before and after sync, and when an overgeared piece has more than a melded one at the cap. It compares the same slot at every item level against a melded piece at the cap, with how each stat is built, checked against real gear and the Wiki. Its Slot menu has one choice per group of slots that share a budget share (Head / Hands / Feet, Body / Legs, and Accessories for the four accessory slots; Weapon, and for a job with a shield (Paladin, Beastmaster, White Mage, Black Mage) Off-hand, alone; the Weapon there is the one-handed weapon, 100 per mille, and a two-handed weapon is not offered), since slots in a group get the same numbers. Its Materia slots menu sets how many stones the example piece takes. It lists the totals real pieces of the chosen slot have (item database, item level 200 and up): armor 0, 2 or 5; accessories 0, 1, 2 or 5; weapon 0, 1, 2, 3 or 5; off-hand 0, 1 or 5 (no piece has 4), and shows the usual one until another is chosen (armor 2, accessories 1, weapon 2, off-hand 0). A slot change that leaves a choice the new slot's pieces lack goes back to the usual one. Every slot is an ordinary one that takes any grade; overmeld odds are not modelled (a 5 is what overmelding allows). More slots than the piece at the cap has room for add nothing, since each stone fills a substat up to its cap.
  - Under "Stat budget analysis, step by step", each stat is the lower of the piece's own value and its ceiling (the most the synced item level allows for that stat on that slot, not a real piece), with the slot shares of the budget.
  - A "?" button opens a popover on how gear stats and syncing work.
  - The example piece's melds go into the two chosen substats, the 2nd first, since the 1st is already at the piece's own cap.
- **GCD Scaling**: how speed becomes the GCD at a level ([math.md, section 6](../mechanics/math.md#6-speed-and-substat-tiers)), on its own settings, whatever the job, sync or optimizer result:
  - *Settings:* a level (the synced level until another is typed; one out of range is corrected), a haste (none, or a job's always-on haste from [math.md, Haste](../mechanics/math.md#haste), listed by job and source name with no percent: the percent the level has is among the facts and every step of it is a label on the chart; `HASTE_OPTIONS` in `views/gcd.js`) and a total speed.
  - *Shows, for the speed:* the GCD, GCDs per minute, the speed to the next step, the cut to cast and recast times (`recastMult`), the tick multiplier and the haste.
  - *Haste menu:* sized like the Clan box (`.sized` with a hidden copy of every text, `HASTE_SIZER`), so it is as wide as its longest name in whatever font the page has and picking moves nothing. Every select's text is one line cut at the box (`overflow: hidden`, `text-overflow: ellipsis`; a customizable select, Chrome and Edge 135+, clips without an ellipsis).
  - *Chart:* the speed one 0.01 s step takes at every level (the first ten steps' average, the haste's levels marked, each with its percent: "15% at 40").
  - *Steps:* 13 steps around the speed, the speed's step in the middle unless it is near the base or the floor.
  - *Slider:* it runs from the level's base to the most total speed any job can have there (the numbers are in [math.md, section 6](../mechanics/math.md#6-speed-and-substat-tiers)).
- **Substat tiers**: where each substat's tiers start, as on the character panel ([math.md, Substat tiers](../mechanics/math.md#substat-tiers-breakpoints)). A card per substat shows every tier of it from its base up to the most a box takes: Points (the range of panel values that give the row's effect, "341–342", "343" for a single value, "365+" for the last tier), the effects, then spare and to next under the rows. Values are typed or clicked, held to the base and the most the level allows. Each substat has its own "?". Its note is one element, `<gsa-stat-note>` (a Zag popover, `#t-pop`, named by its heading): it hangs under the pressed "?" (8 px below it, 20 px left of its left edge, kept inside the window; `z-index` 1) and scrolls with it, under the pinned math bar. A second "?" moves it, a press on the open note's own "?" closes it, Escape closes it with the focus on that "?", and a press outside, Tab to another control or another layer opening closes it; the focus stays on the "?" when it opens.
  - *Job and level:* its own Job box in the math bar's controls row (the job is saved apart from Stat Allocation's and defaults to Paladin), and its own level box, at the job's level cap until another is typed. Stat Allocation's level and sync settings never reach it, and it has no item level. Each valid level counts as it is typed, so the tiers at level 80 can be read while the settings say 50. The optimizer result never comes in (the sub-tab has no Auto-fill button).
  - *Scrolling:* each card scrolls its own rows (a keyboard-reachable region named after the substat), about 15 rows tall in every card, so the tab is no taller than before. The card's header (name, box, effect lines, haste) and footer, and the column names, stay put. The value's row goes to the middle of its card when the tab first shows, when the job or level changes and when a value is typed in its box, but not when a row is clicked (the list does not move under the pointer). The scroll position is not saved.
  - *Rows:* one per tier, so a card has 32 to 645 rows at level 100 (Direct Hit the most, speed the fewest) and a job 1,077 to 1,441. The most a box takes is the same for every substat: its base plus the most gear points any job can have of one stat at the level (`MAX_SPEED` less the base speed), the last row reading "N+". A card draws only the rows around the ones in view, padding the rest (`src/ui/tier-window.js`), since drawing all of them cost about 0.3 s more per job or level change at 4x CPU slowdown; a row is plain text and one data attribute.

## 5. The level and cap fields

The Job and sync settings (job, synced level, item level sync and its cap) are one set per place. The Gear browser shows them in a strip under the tab bar; Stat Allocation shows them in its math bar (the Job box and the Sync settings chip, below); Substat tiers has only a Job box and GCD Scaling none. The Gear browser and Stat Allocation each keep their own job, level, sync switch and cap, saved apart (`browse` and `piece`), and Substat tiers its own job (`tiers`), so changing one leaves the others as they were. The Sheets tab has no panel: each sheet holds its own job, level and sync (section 6).

**The Gear browser's strip** is one narrow strip with no open and closed states. Left to right:

- the Job box: the job's icon, its name and its short code in muted parentheses, with a chevron; it opens the job menu;
- Synced level, Synced item level and the Item level sync switch;
- a Reset button at the right (it asks before resetting the tab's settings to their defaults).

Its behaviour:

- The job menu lists the jobs one line per role (the role's name, then its job icons); the selected job is at full brightness and the others dimmed. Picking a job closes the menu and switches at once, with no question (`requestJob` in `components/job-menu.js`, the one menu of the strip and of the math bar; its markup is `partials/job-menu.html`). Escape or a click outside closes it, and Escape puts the focus back on the Job box.
- The default job is Paladin; there is no "no job" state, and a saved job id that is not a known job becomes Paladin.
- A number field's range ("1–100") sits at the right end of its label line, over the box's right edge (`.f-range` in a `.f` label).
- The Job, level and cap boxes share one width (the widest "Name (CODE)", 210 px), so the strip is one row at 960 px. The item level field has no line under it: a lowered or invalid cap shows as a flag in its label line, in the range's place (the field's flag, below), so the strip keeps its height and no control moves.
- The strip sits under the tab bar with the page's gap above it, so the tab bar does not move between tabs; the Gear browser's content is lower than Sheets' by the strip's height and that gap. The strip scrolls away with the page. How the math works has no strip.
- Reset resets the Gear browser's settings only, after the browser's confirmation dialog. How the math works has no Reset button.

**The math bar** (`#m-bar`, `src/styles/math-bar.css`) is pinned flush at the top of the window while the page scrolls, with 12px under the tab bar's rule when it is not. It has the sub-tabs (with a "?" at the right end on Stat Allocation) and a controls row under them:

- *Stat Allocation:* a Job box labelled "Job"; the Slot menu; one "Substats & materia" chip (the 1st and 2nd substat and the Materia slots menus open from it, e.g. "CRT · SkS · 2 slots"); one "Sync settings" chip ("Lv 85 · IL 270", "Lv 100 · IL 690" while only the level syncs gear, "Unsynced", "Lv 85 · Enter IL" in red while IL Sync is on with no item level) whose popover holds the Level box, the Synced IL box with its flag and the IL Sync switch (the Level box flags text that is no whole level from 1 to the job's level cap, like the Synced IL box: a red flag "1–100 only" in the label line with the sentence `LEVEL_TEXT.typedBad` as the box's name for a screen reader, the chip's text red; the stored level stays as it was, and a valid level, a job or tab change, or closing the popover ends it; the Gear browser strip's Level box has no such flag: it moves a level out of range to the nearest one when it is left); then the Gear item level slider with its number box. A gold mark after the Sync settings label marks level sync's item level for a weapon or off-hand as a guess ([math.md, section 5](../mechanics/math.md#5-item-level-sync)). The chips' texts and their widest forms are constants (`PIECE_CHIP_TEXT`, `SYNC_CHIP_TEXT` in `views/sync-explainer.js`); a hidden copy of the widest form gives each chip its width, so no control moves when a choice changes.
- *GCD Scaling:* its own controls (level, haste, speed) and no Job box.
- *Substat tiers:* a Job box and its level box.
- Every box is one height (`--box-h`, from the text size). The controls row is a container with three layouts by its own width, in rem so they follow the text size: one row at 78rem (1,248px at 100% text) and wider, two rows down to 56rem (the item level group alone on the second), and Job | Slot and chips over Sync | item level under that. Thin rules between sections are drawn by CSS and never start or end a line. The sub-tabs keep their width when one is selected (a hidden bold copy of each label).

**Item level sync and the cap in the math bar.** Stat Allocation's cap follows one rule, applied in user-action handlers only (`holdLevelSyncCap`, `levelSyncCap` in `src/ui/job-sync-panel.js`): switching IL Sync off stores the item level that level sync gives (nothing at the job's level cap); while it is off, the cap follows the level box, the job, Reset and a load; switching it on keeps that cap, and the page lowers it to what the level allows as above.

The rule the level and cap follow is that a cap above the highest gear made for the level is lowered to it. It is in [math.md, section 5](../mechanics/math.md#5-item-level-sync). Without it, a cap alone gave a level 50 character item level 400 stats and a 1.50 s GCD ([history.md](../history.md#stat-model-and-data)). This section is when and how the page applies it. A sheet's page and its New sheet and Copy sheet forms apply it the same way, through the same function ([sheets.md, "A sheet's level and sync"](sheets.md#a-sheets-level-and-sync)).

- **When.** The page lowers the cap only while item level sync is on (`limitCapToLevel` in `src/ui/level-cap.js`). It does so:
  - once the level field settles (typing 80 passes through 8);
  - when a cap is entered;
  - when item level sync is switched on;
  - on loading a saved state.

  The job does not matter: a job at its own level cap (Beastmaster at 50, Blue Mage at 80) is limited the same way.
- **The field.** It takes any whole number of 1 or more, so 999 is lowered the same way, with a flag in the label line and a gold flash of the field. The flag is a triangle icon and "Max 135" in gold, in the place of the range ("1–795"); the whole sentence ("Lowered to 135, max for level 50.") is the field's tooltip and a live region for screen readers. The flag stays until the next change, and stays put when the up arrow is pressed at the limit. Other text (0, 12.5) is an error flag in the same place, a circle icon and "1–795 only" in red, with "Enter a whole item level from 1 to 795" as its tooltip and live region, and the cap stays as it was; the error replaces a lowered flag. On the Job and sync strip, an empty cap with sync on is its own error: a circle icon and "Enter a cap" in red (no range in it), with "Enter a sync cap" as its tooltip and live region. The field shows the cap that applies. The Job and sync strip, Stat Allocation's Sync settings popover, the sheet page and the New sheet and Copy sheet forms (which show no error) all use it (`cap-flag.html`, `capFlag` in `src/ui/level-cap.js`); Stat Allocation's Level box uses the same flag (`levelControls` in `components/cap-controls.js`, `LEVEL_TEXT` and `levelTextBad` in `level-cap.js`). The Level and Item level boxes of a sheet's page and of the forms are 160 px wide, wide enough for "Item level" and the longest flag, so the settings row is one line at 960 px.

## 6. The Sheets tab

The tab has three levels: the **sheet manager** (every saved sheet), a **sheet page** (one sheet: its settings and its gear sets) and a **set page** (one gear set). Which sheet or set is open is never saved: the address names it (section 1, Addresses), a reload opens the same screen and a bare address opens the manager. The saved shapes and the storage rules are in [sheets.md](sheets.md) and [architecture.md, section 4](architecture.md#4-persistence).

**The sheet manager.** One row per sheet, in the user's order, with:

- the name (a link that opens it), the first line of its description ("No description" without one) and the actions Open, Edit, Copy and Delete; a click anywhere else on the row opens the sheet too (see "Opening a row" below);
- the job's icon and name;
- "Lv 100 / IL 123" ("IL sync off");
- the number of gear sets;
- the dates it was created and last changed, in the browser's time zone (saved as UTC times);
- the game patch of the data it was made with ("7.56"; the Patch column): the newest patch released on or before the date of the sheet's data (`patchOnDay`; [the patch table](data-pipeline.md#the-patch-table)), with "Game data d9582a6, 2026-09-30" (the data's short commit and date) as the cell's hover text. The cell is empty when the sheet names no data date, or a date before the first patch.

With no sheet, a "No sheets yet" card with New sheet takes the list's place; with sheets, New sheet sits at the right of the heading. Records the page cannot read are listed under "Could not be read" with their cause and a Delete button.

**Opening a row.** In the sheet manager and in a sheet's list of gear sets, a click anywhere on a row opens its sheet or set (`openRow` in `components/sheets/open-row.js`): the figure cells, the job, the description and notes lines, the origin line, the empty end of the action line and the gap beside the drag handle. It does not open on the row's own controls (the name link, the Open, Edit, Copy and Delete buttons, the drag handle) and not on a click that ends a text selection, so selecting a note to copy it stays possible. A row is found by its id, so a sorted list opens the row clicked. The name link is still the keyboard and screen-reader way in (it is a real link; Tab and Enter work as before): the row has no role and no tab stop of its own, so a screen reader announces one control per row. The pointer is a hand over the rows, and a row is tinted (`--surface2`) under the pointer and while its name link has the keyboard focus, with no change of layout (`#tab-sheets table.sets tbody tr` in `sheets.css`).

**New sheet** is a dialog: a name, a description (optional), the job (the Job and sync panel's icons; fixed once the sheet is made), the level (held to the job's level cap), item level sync and its cap (the highest real item level at first). While no name is typed, the name follows the job, level and sync ("White Mage Lv 50 ilvl 130"). A sheet needs a job and a name that is not empty after trimming; a refused form stays as it is (a blank name stays blank) and shows its reason where the Dialogs item says. The new sheet goes to the top of the list and its page opens.

**A sheet page.** A breadcrumb "Sheets / <sheet>", then the sheet's panel. A lighter banner on top holds the job's icon (44 px), the job's name in small capitals above the sheet's name, the name (two lines at most, then an ellipsis; the whole name is the tooltip), the description (two lines at most; "No description" in dim text when empty) and the Edit, Copy and Delete buttons, each an icon and a word, at the top right level with the icon. Below the banner, the settings keep the panel colour: the level, the item level and the item level sync switch; the job cannot change, so it is not a field. Level and item level sync apply as they are typed, with no question, and every gear set is shown under them; the cap is kept while sync is off.

At the right end of the same row, level with those fields and with their labels on top, are two boxes, each one native select (`.sheetbonus`):

- **Race / Clan** (accessible name "Race and clan"): "Select Race/Clan" (no clan), then the 16 clans, each under its race as an `<optgroup>`. Where the browser draws the open list from CSS (`appearance: base-select`, `src/styles/controls.css`), a race is a small, muted, upper-case heading with a divider above all but the first, and its clans are indented.
- **Party bonus**: "No party bonus", then "1 unique role (1%)" to "5 unique roles (5%)".

Both change the totals of every gear set below (the main stat and Vitality, see [sheets.md](sheets.md#a-sheets-clan-and-party-bonus)) and are disabled while an Auto-fill runs. A select is only as wide as the option it shows, so each is wrapped in `.sized` with a hidden copy of all its texts (`.sizertext`, one per line, in the same grid cell): the box has the width of its longest text whatever is picked, and picking moves nothing. With less room (at 960 px) the pair wraps to a second line of the panel, still at the right.

Under the table of gear sets, one line (`#sh-bonus-note`, the text of `views/set-totals.js` `bonusNote`) says what the bonuses changed in the totals. With no bonus it holds a blank and is hidden (`visibility`), so it keeps its line and setting a bonus moves nothing below the table.

Below the panel, "Gear sets": one row per set, in the user's order, with:

- its name (a link to its page) and the first line of its notes; a click anywhere else on the row opens the set too (see "Opening a row" below);
- how many slots are pinned and unpinned (and how many are empty);
- the actions Edit, Copy and Delete;
- the set's figures under the sheet's settings (main stat, GCD, Critical Hit and its damage, Determination, Direct Hit, the special substat where the job has one, DoT/HoT).
- A switch on the heading line, "Effects | Stat points", chooses what the figure columns show for every set: the effects above (the default), or the stat points the set page's Total row shows (one column per stat of the job, with the meal and the character's base, the character panel's numbers). The choice is kept in the saved state (`sheetFigures`).
- Every heading of the list sorts it, as in the Gear browser: a click sorts best first (names A to Z, the GCD lowest first, every other figure highest first; a GCD with an always-on haste sorts by the hasted GCD, then by the GCD shown in front of it), again flips it, a third click goes back to the saved order. The sort is display only and not saved, and the Effects / Stat points switch goes back to the saved order: the rows' own order is the one the user set, so drag and the arrow keys are off while a sort is on. The figure columns have fixed widths in both views (each the room its widest text needs); the Set column takes the rest.

With no set, a "No gear sets yet" card with New set takes the list's place.

**A set page** has a header that stays at the top of the window while the table scrolls under it:

- **The breadcrumb** "Sheets / <sheet> / <set>", with a caret after the set's name that opens the set switcher (the sheet's other sets, "All gear sets (N)" and "+ New set"): the element `<gsa-switch-menu>`, a Zag popover with a plain list of links (a set's address, so Ctrl+click opens it in a new tab; no `role=menu`). **Keys:** Enter or Space on the caret opens it with the open set's row focused; Tab and Shift+Tab move over the rows; Enter on a row follows it; Escape and a click outside close it with the focus back on the caret; Tab out of the list closes it and the focus moves on. Beside it is the sheet's settings as one read-only line ("White Mage · Level 70 · Item level sync 300"). On a sheet page the caret after the sheet's name switches sheets the same way.
- **The heading** has the set's name in a serif face, with **Edit** (opens "Edit gear set"), **Copy** and **Delete** at the right of the same line, and the set's notes under the name in muted text, all their lines (no line when the set has none, so the set bar moves up).
- **The set bar** follows the state of the set:
  - *At rest:* Auto-fill ("Auto-fill 4 slots": the unpinned rows the job uses, plus the meal while it is not pinned; off with nothing open), the goal ("for MND › CRT"), and a gear button that opens the Auto-fill settings. Auto-fill starts only from this button.
  - *A draft waits:* Apply and Discard only.
  - *An Auto-fill result waits:* Apply and Discard, then the goal.
  - *An Auto-fill runs:* "Solving…" and Cancel.
- **The stat block:** the figures of the sheet's settings as "Total". They are the main stat, GCD, Critical Hit and its damage, Determination, Direct Hit, the special substat where the job has one, and DoT/HoT. While a draft or an Auto-fill result waits, it shows "Now" and "After" with each change in green (better) or red (worse), a lower GCD counting as better.
  - A job with an always-on haste (Monk, Ninja, Samurai, Viper) has the label "GCD (with Haste)" and shows the GCD without the haste, then with it: "2.49s (1.99s)". The delta lines compare the hasted GCD, and the Tier row's caption reads "spare · to next tier (hasted speed)", since its speed tier counts the hasted GCD's steps. The GCD column is wider in the stat block and in the sheet page's list of gear sets.

Under the header: the gear table. Each row has:

- a pin before the slot's name (filled: pinned, outlined: not);
- the piece as a button that opens the **piece picker**: every piece of that slot the job can wear, grouped by expansion newest first, with a search box over names and gear categories. A row that holds a piece also has an "Empty" button (named "Empty this slot") at the right of the search box. A Unique ring already in the other ring row is shown but cannot be picked; a piece that covers other slots (a 2H weapon the Off-hand, a cloak the Head) takes the covered pieces off in the same draft change, emptying and unpinning their rows, and the page's note names them and the cause ("Tidal Wave Buckler removed due to two-handed weapon."; "Rainbow Cap of Healing removed due to Vermilion Cloak of Healing."). While a piece that covers a row is held, that row reads "Unavailable" (hover: "Covered by <piece>"; on the Off-hand under a 2H weapon, the rule below) and its button is disabled (`aria-disabled`, so a keyboard still reaches it), with "Only a one-handed weapon allows a shield." under the Off-hand; a piece for a covered row is refused (`placePiece`: a shield under a 2H weapon, a head under a cloak), so a set never holds both;
- one chip per materia slot that opens the **materia menu**.

The materia menu:

- It shows the four most valuable grades the slot takes, or all twelve with "Show all grades"; a cell the piece's cap already reaches is marked.
- An overmeld slot adds an "odds" row under the grades with each grade's meld chance, and a note when the piece cannot be high quality (NQ rates; display only, the search counts every meld as a success). A grade the slot cannot take (the item level is too low, or a high grade in a small slot) shows a dash, not 0%.
- Only the last stone can be removed, so no chip moves; an empty slot's menu has no Remove button.

The Food row's menu is described in section 2.

**Where the table's menus sit.** The piece picker, the materia menu and the Food menu hang under their button (absolute, `z-index` 3) and are drawn over the table's cells and under the column names (4) and the sticky header (8), so a menu scrolled up under them never covers the Apply bar or the stat block. On opening, `keepMenuInView` (`ui/components/set-page/menus.js`) scrolls the page so the menu's button, not the menu's top, is 8 px under the column names, and cuts a menu taller than the room (button's box included) to a height that fits and scrolls inside.

- **Edits by hand make a draft.** A piece, a stone or a meal chosen by hand changes a copy of the set, not the set. The changed rows are tinted and the stat block shows Now and After. Apply ("Apply 2 changes") saves the draft while Discard drops it, each with a note at the window's bottom. A piece or stone chosen by hand pins its row, and a meal pins the meal. Auto-fill is off during a draft.
- **Pins** are saved as soon as they are clicked, draft or not. Auto-fill keeps a pinned row as it is and fills the others.
- **Auto-fill** runs the search (section 2) with the set's Auto-fill settings (saved with the set at the first Auto-fill: the defaults until then) and its pins, in the set's own lane of the solver. While it runs, Auto-fill becomes Cancel and every edit on the tab is off.
  - *Result:* it waits as a suggestion: the rows it changes are tinted, each with a "Take" box, and Apply saves only the rows taken; Discard (or Escape) drops it.
  - *Empty slot:* a slot the result leaves empty is named in a line under the header. This happens when no piece of it has an equip level up to the one under Gear to search ("Weapon: no Sage piece up to equip level 50, the lowest needs level 60.", `suggestionView`'s `emptyNote`).
  - *While it waits:* pieces and stones cannot be changed (a click on the table says so).
  - *Nothing found:* an Auto-fill that finds nothing, or a pin no set can keep, says why in a line under the header. A piece or meal that cannot be used (missing from the game data, in the wrong slot, one the job cannot wear or eat) is unpinned, and the line names the rows without the reason ("Head and Food unpinned. Auto-fill again to fill them."; the meal is "Food", as in the table), so the next Auto-fill does not meet it again. A relic's row is unpinned with its reason ("Weapon unpinned: Auto-fill can't count a relic's substats."). Pieces that cannot be worn together get their own line ("The pinned pieces cannot be worn together."), name no row and drop nothing.
- **The Auto-fill settings** (the gear button, at rest only) open a popover, not a modal dialog: left-aligned under the set bar, over the table, up to 900 px wide (the bar's width at the 960 px floor), with no backdrop and no title, only a close button (X) at its top right. It has two blocks:
  - *Goal* first: Maximize, Tiebreak 1, Tiebreak 2 and Target GCD (two columns, with "exactly" / "or faster" beside the box), then the Materia and Food switches and "Spare points to tiebreaks" with its ? note, and the line that says a pick moved another rank. The Goal and Gear to search grids and the switch line share five columns (150 px at least, 16 px apart): the Target GCD box is the fourth and "exactly" / "or faster" the fifth (they end and start where the item level pair and Gear categories do), Materia and Food take the first two, and "Spare points to tiebreaks" starts on the third (where Tiebreak 2 and the item level pair start). A smoke step (`checkSettingsAlignment`) checks these edges at 960 and 1280 px.
  - *Gear to search* second, with its count ("· searching 1,408 of 2,805 pieces"): Expansion, Equip level, Item level (min – max, two columns) and "Gear categories". The grid is five columns wide at 900 px. When the count says 0 pieces, the Auto-fill button is off and its `title` reads "No piece matches Gear to search." A gold chip "No pieces to search" (warning icon, the same sentence as its tooltip) follows the gear button on the bar, and a hidden live region (`#sh-no-pieces-note`, always in the bar) carries the sentence for screen readers (`searched` in `gearToSearchView`, `fillButton` and `noPiecesFlag` in `set-page/view.js`). The count refreshes when the page opens, when the settings open and after a settings edit.
  - The settings have no start or Save button: they are saved as they change (a change drops the set's tagged "best for goal" meals; the gear is not on the bar while a result waits, and `editFill` refuses an edit then, so a result is never out of step with the settings), and Auto-fill starts from the bar only. Starting it closes the popover.
  - *Closing:* the gear button, the X, Escape or a click outside close it (a layer of the overlay manager, [architecture.md](architecture.md)). Escape closes the innermost layer first: an open menu or the Spare points note, then the popover. The gear button, the X and Escape put the focus back on the gear button; a click outside leaves the focus where the click went. Tab out does not close it. A draft, a result or a running Auto-fill (the gear leaves the bar) closes it too.
  - *Focus and roles:* it opens with the focus on Maximize. It has `role="dialog"` named "Auto-fill settings" and no `aria-modal`. Tab is not trapped: it runs through the boxes in the order drawn (the X first) and then on to the table.
  - *Floating menus:* the Expansion and Gear categories menus (Zag popovers, `ui/elements/gear-browser/filter-popover.ts`) and the Spare points note (`placeMenu` in `ui/components/filter-menus.js`) float over the popover, fixed to the window. A menu opens under its button; when it does not fit there and there is more room above, it opens upward instead, so the whole Gear categories menu shows at every window from 960 x 700; with no room on either side it opens under the button, cut to the window and scrolling. `placeBelowOrAbove` holds the note's arithmetic. The popover has no transform, so they stay fixed to the window, and a click inside them is not a click outside the popover. The Spare points note is placed again on every window scroll (a scroll of the popover's own box counts, a scroll of the note itself does not) and resize while it is open, as the two menus are.
- **Leaving the page** (a breadcrumb link, the set switcher, Copy, New set) asks first while something is unsaved or running:
  - a draft ("Apply and leave", "Discard and leave", "Keep editing");
  - a running Auto-fill ("Leave and cancel the Auto-fill", "Keep waiting");
  - a waiting result ("Leave and discard the result", "Keep reviewing").

   A tab link that leaves the Sheets tab asks the same question (`components/page.js` `goTab`).
- **Keys.** Escape closes the open menu or the ranking help (in the Auto-fill settings the menu takes the key itself and puts the focus back on its button), then the Auto-fill settings, then the question (as Keep), then drops a waiting Auto-fill result. Tab stays inside the question; the Auto-fill settings are not modal.

**Where each action lands:**

| Action | Lands on |
| --- | --- |
| New sheet | the new sheet's page |
| Copy sheet | the manager, the copy at the top, with a note ("Copied as “Heal (1)”.") |
| Delete sheet | the manager |
| New set | the new set's page ("Set N", the smallest number free) |
| Copy set | the list, the copy right after the original |
| Delete set | the list |

Notes:

- **Names.** Names of sheets and sets need not be unique, are trimmed, and may not be empty (a refused blank name leaves the box empty, marked, with the reason at its label). The name field takes at most 60 characters (the saved data has no limit). A long name is cut with an ellipsis in lists, with the full name on hover. A copy is named "<name> (1)", or the first number free ("X (1)" copies to "X (2)").
- **Edit sheet and Edit gear set.** Edit opens the "Edit sheet" dialog for a sheet (from its row or its page) and the "Edit gear set" dialog for a gear set (from its row or its page). Descriptions keep their lines, and the box takes at most 400 characters (`DESCRIPTION_MAX_LENGTH`; the saved data has no limit); a gear set's description is its notes.
- **Copy sheet** asks for a name (the copy name at first), the job (the jobs of the sheet's gear group, its own included; a Blue Mage or Beastmaster sheet copies to no other job), the level and item level sync. Some of the sheet's pieces may be ones the chosen job cannot wear (by the item's job list, on every row, the off-hand of a two-handed job included). The dialog then lists them by set, slot and name, and Copy sheet stays off until "Clear these pieces in the copy" is ticked. In the copy those rows are empty and their pins dropped. The gear groups come from the item data (`src/data/gear-groups.json`). A "?" after the dialog title opens a panel under it: what a copy keeps (every piece the new job can wear) and clears (the weapon, and any other piece unique to the old job; they are unpinned) and which jobs copy to which, from the same groups (`copyHelpView`, with the sheet's own group marked).
- **Delete** always asks first, naming the sheet and its number of gear sets, or the set. There is no undo.
- **Reordering.** Each row of both lists has a handle at its left: drag it above or below another row (a line marks where it drops), or focus it and press Up or Down arrow. The handle keeps the focus, and a live region reads where the row went ("Set 2 moved to position 1 of 2.", "Heal is already first."). New sheets go to the top.
- **Dialogs.** One at a time, over a dimmed page. Escape or a click on the dimmed page cancels, Enter in a one-line box presses the main button, Tab stays inside, and the focus goes back where it was.
- **Why a New sheet, Copy sheet or Edit dialog was refused.** The dialog stays open exactly as it was (a blank name stays blank; nothing is put back) and shows the reason in the label row of the field it is about, at the right of the label text, in red with a Remix error-warning-line icon (`src/partials/dialog-error.html`, class `dlgmsg`, `role="alert"`): the Name label ("Name cannot be empty."), the Job label, a row of its own above the job icons, on New sheet and Copy sheet ("Choose a job."), or the tick box line of the Copy warning block ("Tick the box to clear the pieces the job cannot wear."). A reason about no field ("The sheet is gone.") shows in the title row, at the right. The field is marked: a red border on the Name box (a red focus ring too, so the ring cannot hide the border), a red outline round the job icons, a red border on the warning block and tick box. The box carries `aria-invalid` and `aria-describedby` naming the reason. The label rows are 18 px high whether they hold a reason or not, and the tick box line keeps its height, so the buttons do not move when a reason comes or goes (smoke step `checkDialogErrors`, at 960 px). Which place shows a reason comes from the data, never from its words: the store's refusal carries `field` (`FORM_FIELD` in `sheets/ops.js`: `name`, `job`, `ack`; none for a reason about the sheet), `submitDialog` hands it on, the component keeps it as `dialog.errorField`, and the view (`errorPlaces` in `views/sheet-forms.js`) puts the text under `errors.name`, `errors.job`, `errors.ack` or `errors.title`. Any edit in the dialog (typing, a job, a number, the sync switch, the tick box, the description) clears the reason (`clearDialogError`); pressing the main button again may bring it back. The Delete question keeps its reason beside its buttons.
- **While an Auto-fill runs** every edit action on the tab is off: New, Edit, Copy, Delete, reordering, the level and sync fields, and the set page's own edits.
- **Saving.** Each change saves the one sheet it changed, at once. A full storage keeps the change in the page, with the storage's message above the tab; with storage blocked, a line says the sheets last until the page closes.

## 7. Corner radii

One radius, 4 px, for every box, field, button, table, menu and dialog. There is no radius token: each rule in `src/styles/` writes `4px`. Exceptions are round on purpose: switch tracks (12 px) and knobs (50%), radio buttons and rank badges (50%), the ? help buttons (50%), origin pills, the Food menu's stat pills and the Gear browser's search bar, clear button and Reset button (999 px; the Slot button is square on its right side, inside the bar), and the 2 px items (range tracks, the search mark, legend swatches). The smoke step `checkRadii` (`tests/e2e/smoke.mjs`, table `RADII`) measures each surface below in the browser, so a rule that drifts fails it.

| Surface | Radius |
| --- | --- |
| Fields, selects, menu buttons, buttons (primary, danger, link, icon, caret), the piece and food buttons, stone chips | 4 px |
| Panels, stat block, notes, callouts, tables' boxes, the segmented control | 4 px |
| Piece, food, stone, breadcrumb and Auto-fill settings menus, with their search boxes and rows | 4 px |
| Dialogs (New sheet, Edit, Copy, Delete, the leave question) and the Auto-fill settings popover | 4 px |
| Scrollbar thumbs | 4 px |
| Gear table, stuck column-name row | top corners 4 px (first cell left, last cell right), middle cells square |
| Gear table, last row | bottom corners 4 px (on the body, first and last cell) |

The gear table draws its own outline so the stuck column-name row has real rounded corners. It needs:

- separate borders (`border-collapse: separate`) with the outline on the cells;
- no border and no `overflow` on the wrapper (an `overflow` of `auto` stops the sticky row, `clip` cuts off menus);
- the stick offset equal to the page header's height (not one pixel less, which hides the cell's top border);
- a 4 px page-coloured wedge (`th:first-child::before`, `th:last-child::before`) in each top corner, so the rows scrolling under the stuck row do not show their square side borders through the curve.

`checkRadii` reads the corner pixels at 2x device scale, in a 1920 x 950 window scrolled to the page bottom: every pixel outside the arc must be the page colour.

## 8. Stacking scale

Every `z-index` in `src/styles/` names a `--z-*` token from `tokens.css` (`--z-row` 1 up to `--z-nested` 70; `--z-dialog` and `--z-toast` share 30). A unit test (`tests/unit/styles/z-index-scale.test.js`) fails on a bare number. A menu inside a library positioner (`[data-part="positioner"]`) is `position: static`, and the page scroll lock follows an open dialog (`.dlg[open]` or `.dlg[data-state="open"]`).
