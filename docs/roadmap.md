# Roadmap: feature ideas

Feature ideas, built or not; each needs the owner's go-ahead. **Built**: ✅ on `dev` at least (live once it reaches `main`), ❌ not yet. The page has felt "overwhelming" before, so a new feature should replace or simplify controls where it can.

Each idea has an ID for referring to it (A1, A2, ...); IDs give no order and are never reused. **Priority**: the build order of the ideas not built, 1 first (owner, 2026-10-15); A3 goes after the features whose settings it saves, A6 (specced, deferred) last. Feature ideas only. Findings and open evidence questions belong on the page they concern; the in-game captures the sync model still needs are in [validation.md, section 8](mechanics/validation.md#8-open-question-in-game-captures).

Related pages: [optimizer.md](engineering/optimizer.md), [materia.md](mechanics/materia.md), [validation.md](mechanics/validation.md).

| A4 | Gear sets and comparison | ❌ | 3 | Keep several gear sets side by side and compare their stats and tiers: optimizer results under different targets or tiebreaks, and sets the player enters (the gear they own). Could also limit the optimizer to owned gear (it searches every piece the job can wear since the gear pool step was dropped, 2026-10-15). |
| A3 | Save and share a result | ❌ | 4 | As a JSON file or a URL. After A1, A7 and A4, so it saves their settings and sets too, and the pieces picked from A9's menus. |
| A6 | Export to and import from xivgear | ❌ | 5 | Export a result as an xivgear link (the set in the URL, with the item level cap; no login or server), import a set from an xivgear link. xivgear drops gear below item level 290 (except Blue Mage and Beastmaster), so the export is off for such sets, with a reason. Needs game item and materia ids in the item data first. Testing: a semi-exhaustive browser sweep (every job, each sync setting, several optimizer targets) that opens each exported set in xivgear and checks items, melds and synced stats against ours, plus import round trips. |
| A8 | Breakpoint visualizer | ❌ | 6 | A view in How the math works: for a substat (speed by GCD; Critical Hit, Direct Hit, Determination, Tenacity, Piety by effect) and a level, where its tiers (breakpoints) start, on the character panel's scale (base + gear), with how many points each tier spans. Built on the tier math the optimizer's Tier row already uses (core/tiers.js, gcdTierAt); checked against AkhMorning's tier tables ([validation.md, section 5](mechanics/validation.md#5-speed-and-gcd)). Owner's request, 2026-10-16. |
| A7 | Rank tiebreaks by tier | ✅ | – | After A1: hold the target at the start of its best tier, counted with food, then maximize the tiebreaks, each held at its best tier in turn. Exact with the engine's stat minimums; gear points for a total with food come from `gearNeeded` (core/food.js). Owner's go, 2026-10-15 (it had been dropped on 2026-10-14 until food and stat minimums existed). Built 2026-10-16: the core ([tier-ranking.md](engineering/tier-ranking.md)) and the page's Rank by tier switch (on by default), readout of the held tiers, highlighted Tier cells and progress bar ([optimizer.md, section 7](engineering/optimizer.md#7-the-pages-pool-and-its-filters)). Open: a full comparison of tier and raw results to settle the default (owner); one case still stops at the node limit (White Mage, level 100, exactly 2.32 s). |
| A9 | Other pieces with the same result | ✅ | – | Each result row shows a piece with the same result (the same main stat and goal points, every other substat at the same tier, with food), the lowest equip level first, and its item cell is a menu of the others, by expansion, each with its gear category; under sync most slots have many ([optimizer.md, section 7](engineering/optimizer.md#7-the-pages-pool-and-its-filters)). The gear category is a field of the item data ([data-pipeline.md, section 4](engineering/data-pipeline.md#gear-category)). Owner's request, 2026-10-16. |

| A5 | Check sync caps against ffxiv-gearing | ✅ | – | Validation only, not an integration: compare our synced stats with [ffxiv-gearing](https://asvel.github.io/ffxiv-gearing/) at every duty sync it offers, as was done with xivgear's meld caps ([materia.md, section 3](mechanics/materia.md)). Built: `scripts/validate/gearing/`, results in [validation.md, section 9](mechanics/validation.md#9-against-another-tool-ffxiv-gearing). |
